# Agent Note: 前端主界面按方向 A（Geist 中性 + Apple 校准）重制视觉语言

Status: implemented

## Problem

2026-11-01 对生产前端做了一轮系统评估，结论是：三栏结构与信息密度已经合格，观感差距集中在视觉语言，而且集中在浅色主题——

- 中栏 pending 行的米黄软底连成串占满首屏，是最大的噪音源；
- 同屏 soft 底色超过 10 种（角色五档、工具七档、语义三档叠加），色彩没有预算；
- 表面层级靠 1px 边框硬分，明度差不足；
- 徽章、图例、行内标签铺色过多，重点信息反而沉底。

深色主题的三层表面加语义色关系成立，可以当基准。需求侧的目标（Pis 原话归纳）：简洁，让用户一眼找到最重要的信息；不要很多副标题、不要冗余信息；视觉负担要低。这与仓库常备约束[前端降噪常备约束](../process/2026-10-24-frontend-denoise-standing-rule.md)同源。Pis 同时明确认可 Apple 的设计语言，要求把 Apple HIG 纳入校准。

外部参考取用截图加 token 加组件解剖的方式（Braintrust、Langfuse、Sentry 的 trace 界面；Geist Colors、Dark Developer UI、Radix Colors、Mars Dashboard 指南），链接只当索引。规格来源是作者本地的参考库、四方向对比页与方向 A 细节样张（含明暗双主题切换），这些工作产物不随仓库发布。

## Decision

总原则：**换视觉语言不改结构**。三栏布局、轮次带与读数卡的分组方式、数据接口全部不动；全部动作只有删减与换值。accent 换 Apple 系统蓝（浅 #007AFF / 深 #0A84FF），三档字色对齐 label / secondaryLabel / tertiaryLabel，字体栈本就是 Apple 栈。

六步全部交付，各步的范围、验证与走查记录在对应 note：[第 1 步 token 值替换](2026-11-02-direction-a-step1-token-replace.md)、[第 2 步徽章与工具降噪](2026-11-02-direction-a-step2-badges-tools.md)、[第 3 步会话栏与顶栏](2026-11-02-direction-a-step3-sessions-topbar.md)、[第 4 步头部摘要块收噪](2026-11-02-direction-a-step4-header-denoise.md)、[第 5 步工具列表页与配对页](2026-11-02-direction-a-step5-tools-pair-page.md)、[第 6 步树图单色化](2026-11-02-direction-a-step6-treemap-monochrome.md)；落地后的逐项对齐见[方向 A 对齐修正](../bug-fix/2026-11-02-direction-a-alignment-audit.md)。

五条设计规则（状态色只给异常与选中；数字一律等宽；分组靠间距与对齐；角色徽章软底 pill 四档封顶、工具七档删除；每个数字自带语境）的现行文本以 [UIUX-DESIGN.md](../../../../UIUX-DESIGN.md) 的信息表达、色彩与色彩预算各节为准，本 note 保留定下它们的依据。

## 已定决策与样张的对应

- **方向 A（Geist 中性）**，2026-11-01 Pis 从四方向对比页选定；同日补充 Apple 校准。
- **头部摘要块保持两栏**，2026-11-01 Pis 否决单栏合并方案；与 [会话头部两栏](2026-11-01-session-header-two-column.md) 的交付一致，第 4 步只做收噪。
- **角色辨识选甲（徽章底回归）**，2026-11-02 Pis 定。三个方案做过同数据对比样张（甲徽章底回归、乙图标前缀、丙角色词上色），我方推荐丙，Pis 权衡后定甲：辨识优先于极简。甲的代价（同屏多四块软色）用三条控制：pill 化把底色面积压到最小、低饱和软底、色相数封顶四档。丙样张保留在细节页区 4 讨论稿；两方案共用同一 DOM，只换徽章 CSS，甲实际使用显吵时可低成本切换。
- **思考与耗时的分档变色机制原样保留**，2026-11-02 Pis 明确要求。口径不动：`web/duration.js` 的 TIER_LIMITS 与 tierOf 分档，中栏行尾经现有类名上色，正常档弱灰、超限琥珀（--warn）、再超红（--bad）；等待型工具不上色。新设计只换色值，不改阈值与判断位置。
- **选中态**：点选请求里的某一条消息，该行浮现 2px accent 左缘加整行浅蓝底；中栏消息行与右栏结构行共用同一样式，单选；hover 仍是灰底。这是 2026-11-02 Pis 提出的硬性要求——选中必须可见。

## Alternatives considered

- **方向 B（Linear 暗色密度）/ C（Radix 演进保留青绿）/ D（观测台时间轴化）**：对比页存档。B 的暗色密度与浅色主题诉求错位；C 保留青绿主色但收敛有限；D 的瀑布化动结构，违背「换视觉语言不改结构」的边界。
- **乙（角色前加图标）**：图标是第二层解码，10px 下糊成墨点，图形不解释含义、旁边还得留字，每行多一列间距成本；Apple 自家列表也不给每行配图标。否决。
- **丙（角色词上色，无底）**：我方原推荐——hue 缩到一个词上，噪音最小。Pis 选甲后降为备选，保留样张与「换 CSS 即切换」的退路，理由见上。
- **头部单栏合并**：把资源/性能与工具/写入/读取并成一栏。Pis 明确两栏更好，否决。
- **引第三方组件库**（分段控件、树图）：仓库约束不引第三方依赖，全部用现有 vanilla 结构实现。

## Consequences

- 交付核对（2026-11-08）：`--tool-*` 七档与 `--k-field` 在 app.css 零残留；角色四档、树图单色四档、内容区选中左缘在生产 CSS 在位。各步验证与生产走查记录见六篇 step note 与对齐修正 note，本 note 不重复宣称。
- 甲方案的密度代价：长会话里四档软底持续在屏。已留丙方案的低成本切换预案（DOM 不变）；若切换，本 note 更新决策记录而非另起炉灶。
- 树图深色 alpha 档是示意值，真实会话验证区分度后可调；不达标就在深色套单独调档，不改结构。
- 规则文本的家在 [UIUX-DESIGN.md](../../../../UIUX-DESIGN.md)；立家过程见[前端设计规则立唯一权威](../process/2026-11-08-uiux-design-rulebook.md)。
