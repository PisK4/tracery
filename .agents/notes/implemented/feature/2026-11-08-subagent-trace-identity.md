# Agent Note: 子代理轨迹的读侧身份与页面标识

Status: implemented

## Problem

子代理的请求与父会话共用同一个 `conv_key`，按 `(conv_key, actor)` 派生，采集、归属、链角色都是对的。问题在读侧：`RequestRow` 只透出 `actor`，不告诉页面「这一笔是子代理收到的输入」。页面于是把子代理的委派提示读成主 agent 的用户命令，同形铺在主链里。

本机实测 18,605 行（12.7%）带子代理身份。`claude` 走 magpie 的 11,598 行里有 8,363 行 `via='through'`、3,227 行 `via='hook'`；其余来自 codex、dsh、zcode、hermes 的本地会话适配器。具体误读三处：

- 中栏：子代理组与主链组完全同形，只有角色 pill 的 `user`，读者无从判断这是发给子代理的任务简报。
- 右栏：关系文案写「会话首笔」。194625 是 Explore 子代理的首次模型调用，它的「首笔」是子代理组内首笔，不是会话首笔。
- 会话标题：`SESSION_TITLE_SQL` 的用户标题候选没有按身份收口。按当前库只读重算，1,098 个有用户标题的会话里 21 个的首个候选行是子代理行，列表直接显示子代理收到的任务简报。

## Decision

读契约透出身份，页面按身份换词，不改采集、不改派生、不动 schema：

- `REQUEST_COLUMNS` 加 `r.session, r.subagent`，`RequestRow` 加 `subagent` 与 `subagent_no`，`projectRow` 接受编号参数原样透出。
- 编号在 `listRequests` 的同一个只读事务里按会话算：`ROW_NUMBER() OVER (ORDER BY MIN(started_ms), subagent) GROUP BY subagent`。按首笔时间排序而不是行序或 id，翻页与窗口变化都不换号。详情走同一条规则，右栏与中栏看到的是同一个 S 号。
- `subagent = session` 的行不编号：droid 的子会话整场就是子代理（本机 2,718 行），在会话内部再标 S1 会把每一笔都写成子代理调用。
- 中栏：子代理组加整组左缘点线与组首行短标 `S1`/`S2`（悬停给完整 id）。选中的实线、失败的实线、缺口虚线与点线四种语义互不重叠。主链行与独立子代理会话一个字都不加。
- 右栏：`relationTextOf` 在 `subagent_no` 非空时换词，「子代理 S1 · 首笔」「子代理 S1 · 续自上一笔」「子代理 S1 · 另起一支」「子代理 S1 · 前驱正文不可读」；头部身份行补「子代理 S1」。
- 会话标题：用户标题候选在原有顺序前面插一级——本会话自身（非折叠子代理）主链 → 任一 actor 主链 → 任一 actor。只插一级、不按身份过滤：直接排除子代理候选会让只有子代理标题的会话退到「hy4-free · 00:01」这类无信息兜底。实测把「自身任一」也升到第二级会改掉 17 个会话标题，其中 6 个换成「Tool loaded.」「## Page contract…」这类首条 user 碎片，比子代理的委派提示更没信息量，所以否决了那版。当前口径按只读重算只改 2 个会话，0 个退到兜底、0 个变短。`getSessionTitles` 的轻量路径共用同一段 `USER_TITLE_SQL`，两条路径不会分叉。

## Alternatives considered

**把「本会话自身任一」也排到「任一 actor 主链」前面。** 直觉上自身优先，实测是反向的：主链候选本来就是会话里信息量最高的一句，而自身 actor 的次链候选常常是「Tool loaded.」「继续」这类工具回执。按当前库重算，这一版会把 17 个会话的标题换成首条 user 碎片，其中 6 个变短到 16 字以内。

**默认过滤子代理行，另给「只看主链」入口。** 这是更大的一次产品改动：默认视图会少掉 12.7% 的行，读者要先学会切换才能看到子代理的调用过程。本次只解决「看见了但读错」，过滤与折叠留给后续 feature（子代理组折叠 / 只看主链切换已记 todo）。

**按连续段折叠子代理组。** 真实窗口里子代理与主链是毫秒级交错的（194625 所在窗口 12 行跨 47 秒），按连续段折叠会切出大量碎片，反而更难读。

**短标用子代理 id 前 6 位。** id 是十六进制串，前 6 位没有会话内次序，也不能和会话头的「子代理 N 个」对上。S 编号与会话内首次出现次序一致，读者可以把它当引用用。

**给独立子代理会话（droid）也编号。** 这类会话的 `subagent` 恒等于 `session`，编号后每一行都是子代理行，标记失去区分力；它需要的是「这是子代理会话」的会话级标签，属于另一个入口。

## Testing

合成数据：

- `tests/queries.test.ts`：编号按首笔时间（后到的 sub-b 拿 S2）、同一子代理跨页同号、主链行与独立子代理会话编号为 null；会话标题先取本会话自身主链候选、子代理标题仍能压过自身的次链碎片、只有子代理标题时降级使用。
- `tests/trace-view.test.ts`：短标只挂组首行一次，完整 id 进 title；不传短标时不出标记。
- `bun run typecheck` 干净；`tests/queries.test.ts` 64 项、`tests/trace-view.test.ts` 48 项、`i18n` 与 `http` 38 项、web 相关 66 项全部通过。

## Consequences

中栏行数不变，只是子代理组多一条左缘点线与组首行一个 9px 短标；主链行逐像素不变。右栏与会话标题的文案按身份收口，主链文案一个字不改。

生产部署后按真实流量复验（8320）：目标会话 30 组里 14 个子代理组都带短标，194625 带 `S1`；右栏写「子代理 S1 · 首笔」；`::before` 计算样式为 `dotted 2px` 点线。会话标题按读路径同口径只读重算，换名 2 个、变短 0 个、退兜底 0 个；`/api/sessions/titles` 复核确认换的是子代理简报，其余不动。

未覆盖：会话列表里仍有「Tool loaded.」这类信息量很低的标题，那是标题派生的质量问题，与本次身份收口无关，不在本 note 范围。子代理组折叠已记 todo；「只看主链」入口已在后续 note 交付。

后续：[子代理阅读视图](2026-11-08-subagent-actor-views.md) 把中栏标记换成实线、组底与首现全名，并采纳本文否决的「只看主链」，默认视图改为主链。本文的读契约、编号规则、右栏文案与会话标题口径仍然有效；标记样式与默认是否过滤两项以新 note 为准。
