# Agent Note: 子代理阅读视图

Status: implemented

## Problem

子代理请求与主链请求按毫秒交错：`Agent` 工具异步启动后，子代理的请求与主 agent 的请求同时落进同一条按时间排序的列表。子代理身份收口（[子代理轨迹的读侧身份与页面标识](2026-11-08-subagent-trace-identity.md)）解决了「这一笔是谁的」，没解决「哪一段是谁的」：真实窗口里不存在连续的子代理段落，组首标记与左缘线只能逐组声明归属，主链仍被一次次切断。会话 `d0b52d1f-…` 的窗口 30 笔请求里，主链 10 笔、折叠子代理 13 笔、辅助请求 7 笔，主链只占三分之一。

会话头里的「子代理 1 个 · 172 笔」说明总量，却不提供把子代理收起来的入口。

## Decision

中栏加阅读视图，默认主链：

- 视图三种取值：`all`（全部，含辅助请求与子代理）、`main`（主链，默认）、子代理编号（只留该 S 编号）。筛选只在已加载窗口内进行，序号仍取窗口位置，被筛掉的请求留出空号。
- 主链视图排除两类行：辅助请求（`isAuxRow`：`purpose_chain='exclude'` 或 `chain_role='aux'`）与折叠子代理（`subagent_no` 非空）。独立子代理会话（droid，`subagent=session`，编号为 null）留在主链视图。
- 视图控件在会话头 facts 行右端，按钮为「全部」「主链」「子代理 S1」…，各带当前窗口内的笔数。窗口里既没有辅助请求也没有子代理时不给控件。
- 全部视图保留归属标记，改成可读形态：组首行首现写「子代理 S1」，之后只写 `S1`；左缘 2px 实线（`--muted`），组底铺 `--inset`。辅助请求不带标记，也不计入任何 S 编号的笔数——它属于 harness，不属于角色的阅读视图。
- 单一角色视图（主链、S 编号）不画归属标记与底色：视图本身就是身份。
- 直达链接、汇总条目、轮次起点落在被筛掉的视图里时，先切到目标行归属的视图再选中。辅助请求没有自己的视图，回「全部」。
- 视图是会话内的阅读状态，不写 URL；换会话回主链。窗口重建后编号视图若一笔不剩，有效视图退回主链。

判定函数放在 `web/trace-view.js`：`isAuxRow`、`viewMatches`、`viewOfRow`、`effectiveView`。装配层只做状态与渲染接线，`session-view.js` 只摊开传进来的选项。

## Alternatives considered

**只加强标记，不做过滤。** 先做过两版标记样张：每组写全「子代理 S1」，或首现写全、其后写短标。两版都留住了并发交错的原样，主链行之间仍夹着整组子代理行与色块；标记只能说明「这行是谁的」，回答不了「这段是谁的」。真实窗口的调用证据也表明子代理段落本来就不连续，按连续段折叠会切出大量碎片。否决。

**给辅助请求单开一个视图。** 样张里提过，落地时没做：辅助请求在窗口里占比不低（7/30），但它们是 harness 的标题生成与动作分类，逐笔阅读的需求低；主链视图已经把它们滤掉，全部视图里仍可见。多一个页签增加选择成本，留给有真实阅读需求时再加。

**默认全部，主链作为可选。** 这正是身份收口 note 里否决过的方向：默认过滤会让 12.7% 的行默认消失。本次用户明确要求主视图是主链：要读子代理过程时切「全部」或对应 S 视图，平时主链保持连续。标记与计数让被滤掉的总量始终可见，控件就在 facts 行，不构成信息丢失。

**把视图写进 URL。** 视图是阅读习惯，不是定位目标。写进 URL 会让同一条 `?trace=` 链接在不同浏览器里打开成不同视图，刷新后的视图状态也会和链接语义混在一起。不加。

## Testing

合成数据：

- `tests/trace-view.test.ts`：`viewMatches` 在全部视图收下所有行；主链视图排除辅助请求、折叠子代理与其辅助请求，保留独立子代理会话；编号视图只留该 S 编号。`viewOfRow` 的归属与 `effectiveView` 的回退。组首标记只挂首行一次，读屏文案按 `subagent_no` 生成，显示文案可以是「子代理 S2」或 `S2`。
- `tests/web.test.ts`：有可过滤行时才输出 `view-switch`，`aria-pressed` 与笔数按视图给出。
- `bun run typecheck` 干净；受影响五个测试文件 142 项通过。

生产副本（隔离实例 8399：生产库只读备份 + 独立 `ATC_DATA_DIR` 与 `ATC_PORT`，未碰 8320）：

- 会话 `d0b52d1f-…` 默认主链 10 组；控件为全部 30 / 主链 10 / 子代理 S1 13；全部视图 30 组、13 个 S1 组（首组写「子代理 S1」，其余 `S1`）、辅助行不带标记；S1 视图 13 组、无标记，序号保留窗口空号（10、11、13、…、28）。
- `?trace=194451`（子代理）自动切 S1 视图并选中第 10 笔；`?trace=194508`（辅助请求）自动切全部视图并选中第 30 笔。
- 切换视图时选中身份保持：切到主链后选中态消失，切回全部同一组恢复高亮，右栏内容不随视图重算。
- 深浅主题、英文界面（All / Main chain / Subagent S1）与 400px 窄屏无横向溢出。
- 未覆盖：测试副本里该会话没有已结算轮次（`/api/sessions/…/turns` 返回 0 项），轮次带点选触发的换视图路径只经过类型检查与代码走查，未在浏览器里实际点过。

## Consequences

中栏默认少显示子代理与辅助请求，主链连续。被筛掉的总量在会话头控件里带笔数，切「全部」或对应 S 视图恢复。全部视图的归属标记从点线小字换成实线、组底与首现全名，逐行扫描更容易；主链视图与 S 视图不带任何标记，主链行与之前逐像素一致。

`chain_role='aux'` 与 `purpose_chain='exclude'` 的判定此前只用在行投影里，现在多了一处视图筛选；两处共用 `isAuxRow`，口径不会分叉。

未做：子代理组折叠（视图筛选已覆盖「先收起再看」的主要需求，折叠仍记 todo）。视图不跨会话保留。
