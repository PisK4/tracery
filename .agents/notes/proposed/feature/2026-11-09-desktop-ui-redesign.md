# Agent Note: 桌面 UI 重构：Tauri 2 外壳与右栏读数

Status: proposed

## Problem

Tracery 的前端现在是一个浏览器页面：44px 顶栏，三栏，右栏 280–640 自适应，读数页把本次回复、请求结构、能力清单、用量与上下文、身份完整性依次堆下去。信息架构已经成立，方向 A 的视觉也已在生产落地。问题集中在两处：桌面化本身，以及右栏在常见窗口下的密度。

桌面化要解决窗口外壳、标题栏与拖动区、服务如何被窗口加载、窗口缩放时的布局。浏览器没有这些。

右栏是检查一笔请求的主工作面。1440×900 下默认首屏已经接近满高；1180×760 下核心读数被挤出视口，用户要纵向滚动才能看到用量与上下文。Pis 的要求是右栏细节不要靠横轴或纵轴拉动才能看到。现有实现里，本次回复只有 finish 与正文，工具与技能混在同一个能力折叠里，用量卡的图例和明细各占一段；请求结构本身已经是 LLM 请求的原始消息序列，按序号、角色与预览一条一行，这个形态是对的。中栏会话概要板已有左右两半的雏形，但每行如何保持单行、溢出如何省略没有固定规则。样张把这版目标画了出来：右栏一屏内同时给出回复、结构、构成与用量，中栏概要板左右分栏、每行一行。

这份 note 把样张固定成可执行的规范，并写清桌面外壳的边界。视觉语言沿用方向 A，不另起一套。

**取代检查。** [方向 A 前端重绘](../../implemented/feature/2026-11-02-frontend-direction-a-restyle.md)持有色彩、字体、圆角与阴影，本文只在这些令牌上增加桌面密度，不改视觉基调。[上下文窗口读数](../../implemented/feature/2026-10-30-context-window-stats.md)持有四个指标的计算口径；本文把 treemap 换成双圆环，改图形与排布，不改公式、分母与缺失态。[Lucide 图标迁移](../../implemented/feature/2026-11-08-lucide-icon-migration.md)持有生产图标体系，本文按语义补图标名，不迁到 IconPark。[会话栏与行层级](../../implemented/feature/2026-11-04-session-layout-and-row-hierarchy.md)持有三栏与右栏滚动边界，本文改变右栏默认宽度和密度，不换布局模型。[插件系统与待办](../../proposed/architecture/2026-11-04-plugin-system-and-todo-feature.md)已交付第五页签，本文只负责样式和计数，不新建 Plugin 机制，也不改待办 DTO。[右栏扁平行](../../proposed/simplification/2026-10-28-rail-flat-rows.md)提出的折叠收编仍在活动树里，本文保留四个 `rail-fold` 与用量折叠，不与其冲突。[读取架构](../../implemented/architecture/2026-11-02-read-architecture-and-client-seams.md)持有读取入口，本文只消费现有读数，不直连 HTTP。[用户设置层](../../implemented/feature/2026-11-09-user-settings-config-tier.md)持有设置面板与写权威，本文只把它接进桌面外壳。[隐私边界](../../implemented/architecture/2026-10-20-privacy-and-local-access-boundary.md)持有监听地址、令牌与脱敏，本文不改这些边界。[会话轨迹汇总](../../implemented/feature/2026-10-25-session-trace-summary.md)持有 `SessionSummary` 的逐条口径、指标梯队与「缺失不等于成功」的立场，本文只重排展示，不改任何公式；[方向 A 第 4 步](../../implemented/feature/2026-11-02-direction-a-step4-header-denoise.md)持有头部摘要块两栏收噪，本文改的是同一块板的展开层，两栏与单行规则沿用；[宣传片场景注入](../../proposed/feature/2026-11-03-demo-scenario-injection.md)规定汇总按生产 `SessionSummary` 含义取数，本文的 KPI 与之同源。这三篇保持活跃，本文不取代其口径。活动树里没有记录持有桌面窗口外壳、右栏四折叠与用量卡排布、桌面密度断点、中栏概要板行序与单行规则这四件事。

## Proposal

Tauri 2 外壳只做窗口宿主，加载 launchd 托管的 `127.0.0.1` 服务，不自带采集器，不向页面暴露文件系统或 shell 桥。窗口默认 1440×900，最小 1180×760，可拉伸；macOS 用原生交通灯与 overlay 标题栏，顶栏 48px 兼作拖动区。

页面保持现有三栏与读取架构，右栏默认宽度改为 480px，允许 280–640。读数页重排为四折叠卡片、用量卡和身份完整性三块，默认只展开用量卡；四个折叠的摘要行承担首屏读数，展开后阅读细节。桌面高度不足时进入 compact 密度：缩短折叠行、压缩双圆环、隐藏用量脚注，四格指标、圆环图例和构成明细不移除。中栏概要板固定为左右两半，左侧性能读数、右侧工具使用，每行只占一行，超出强制省略；底部中下方的分隔栏按钮展开指标详情：两条覆盖堆叠条、三张重点卡，以及默认收起的全部明细；点击卡片外或 Esc 收起，窄宽度下单列六行。

浏览器直接打开时页面铺平整个视口：顶栏与三栏从窗口边缘起排，不留舞台底色、四周留白、圆角与投影，也不设页面级 `max-width` 或居中容器。固定尺寸、原生窗口边框与圆角只属于 Tauri 外壳；`?host=desktop` 决定有没有这层窗口，三栏网格、断点与读取路径两种宿主共用。

视觉沿用方向 A 的令牌，新增桌面密度、折叠行、回复块、请求消息列表、会话概要板、双圆环、构成明细和待办卡这些组件规则。图标继续用 Lucide，样张里的 IconPark 几何只作视觉参考，不进入仓库。

静态样张在仓库外 `.archify/tracery-desktop-demo-20261109.html`，已被 `.gitignore` 排除，数据全部为合成值。样张的作用是固定尺寸、层级和组件形态；数字不是生产事实，不能抄进代码、fixture 或测试。样张默认渲染浏览器平铺形态，桌面窗口、舞台留白与控制条是评审用的第二种宿主形态，只在切换后出现。实现的唯一数据源是 `src/read-contract.ts` 与现有读数模块。

## 窗口与外壳

### 尺寸

| 项 | 值 |
| --- | --- |
| 默认窗口 | 仅 Tauri 外壳：1440×900；浏览器无窗口尺寸，铺满视口 |
| 最小窗口 | 仅 Tauri 外壳：1180×760 |
| 默认右栏宽度 | 480px |
| 右栏可调范围 | 280–640px，沿用现有拖动条与双击恢复 |
| 桌面顶栏 | 48px；浏览器内保持现有 44px |
| 交通灯左侧留白 | 78px |
| 窗口圆角与阴影 | 交给 macOS 原生窗口，不自己画外框 |

窗口可拉伸，页面布局随宽度变化。高度变化只影响右栏密度，不改变三栏结构。浏览器没有窗口可拉伸，视口变化同样只影响布局与密度。

### 宿主与版面

浏览器与 Tauri 外壳共用同一份三栏网格与读取路径，分岔只在窗口那一层：

| | 浏览器（无 `?host=desktop`） | Tauri 外壳（`?host=desktop`） |
| --- | --- | --- |
| 页面占宽 | 铺满视口，`100%`，不留边缘 | 铺满窗口客户区 |
| 外框 | 无舞台底色、四周留白、圆角、投影、模拟交通灯 | macOS 原生窗口边框与交通灯 |
| 尺寸来源 | 浏览器视口 | 初始 1440×900，最小 1180×760，可拉伸 |
| 顶栏 | 现有 44px | 48px，左留 78px，兼作拖动区 |

样张默认按浏览器口径渲染；切到桌面窗口模式才出现 1440×900 的窗口、舞台留白与控制条，`1180×760` 与 `自适应` 两档只用于窗口评审。`?host=desktop` 只切换窗口外壳与顶栏，不换页面骨架，也不新增读取；规则写入 [UIUX-DESIGN.md](../../../UIUX-DESIGN.md) 的「布局与首屏」。

### 顶部栏

桌面顶栏在现有 `.topbar` 上增加宿主样式，不另建第二套导航：

- 左端留出 78px 给原生交通灯，品牌与面包屑从其后开始。
- 顶栏空白区域加 `data-tauri-drag-region`，按钮、输入框和链接不参与拖动。
- 保留现有品牌、面包屑、会话栏开关、右栏开关、语言、主题、设置按钮。
- 刷新按钮留在会话栏标题行，点击后图标旋转 480ms。顶栏不新增第二个刷新入口，避免两条刷新路径。
- 设置按钮打开现有设置面板，不改造后端，不改变服务端权威。

### 加载与失败

外壳加载 `http://127.0.0.1:<port>/?host=desktop`，`<port>` 从与采集器相同的 `ATC_PORT` 解析，默认 8320。页面通过 `?host=desktop` 进入桌面样式；不带参数时就是现有浏览器页面，三栏铺满视口，44px 顶栏，行为不变。

服务不可达时，外壳显示最小失败页：说明采集器未运行、给出重试按钮、提示用 `bun run service start` 启动。外壳不自动启动、不拉起源码、不再起第二个采集器。采集器生命周期仍归 launchd 与 `bun run service`。

`?host=desktop` 是宿主接缝，不是权限。页面不拿到 Tauri 命令、文件系统或 shell。窗口控制只用原生交通灯；页面内不放自定义最小化/关闭按钮。后续若要让页面控制窗口，另写威胁模型与 note。

Tauri 配置保持最小权限：不启用 `fs`、`shell`、`http` 插件，不配置 `dangerousRemoteDomainIpcAccess`，`withGlobalTauri` 关闭。页面与服务的通信仍走现有 loopback HTTP。不放开 CORS，不把监听地址从 `127.0.0.1` 扩出去。

## 布局与密度

### 三栏

沿用现有网格：

```text
sidebar 250px | main minmax(0,1fr) | handle 6px | rail 480px
```

默认右栏宽度由 `480px` 取代现有 `clamp(...)` 的 640px 上限结果。拖动条仍写 `--rail-width`，双击恢复 480。侧栏折叠、右栏折叠与现有键盘操作不变。

右栏是独立滚动容器：头部与页签固定，正文滚动。默认读数在 1440×900 下不出现纵向滚动；展开折叠或进入构成明细后允许滚动。280px 宽度下允许纵向滚动，不允许横向滚动。

### 密度断点

密度按右栏正文的可用高度判定，不按窗口高度。用 `ResizeObserver` 测 `#rail-body` 的 `clientHeight`，在右栏根节点写 `data-density="compact"`：

| 条件 | 密度 | 变化 |
| --- | --- | --- |
| 正文高度 ≥ 760px | full | 四折叠行 29px，双圆环面板约 134px，显示用量脚注 |
| 正文高度 < 760px | compact | 折叠行 25px，双圆环面板约 131px，隐藏用量脚注，卡片内距 10px |

compact 不隐藏四格指标、圆环图例和构成明细。它只压缩垂直空间，信息不减。

宽度用容器查询处理，断点跟右栏自身宽度走：

- 右栏 ≥ 400px：四格指标排成一行；双圆环并排。
- 右栏 360–399px：四格指标 2×2；双圆环仍并排，图例收紧。
- 右栏 < 360px：双圆环单列堆叠，不横向滚动。
- 右栏 < 380px：页签隐藏文字，只留图标；按钮保留 `title` 与 `aria-label`，点击区不小于 32px。

所有宽度都要通过 `scrollWidth <= clientWidth` 检查，不用 `overflow-x:hidden` 掩盖布局问题。

### 默认首屏

读数页默认状态：

```text
rail head：标题 + 来源 + 状态 + 五页签
本次回复      折叠，摘要 finish: tool_use + 3 块
请求结构      折叠，摘要 11 条消息 + 新增 2
工具清单      折叠，摘要 14
技能清单      折叠，摘要 36
用量与上下文  展开：四格 + Token/耗时双圆环 + 矩阵树状图 + 构成明细折叠 + 脚注
身份完整性    异常时出现，默认折叠
```

1440×900、480px 右栏的正文高度约 761px，样张实测 `scrollHeight` 与 `clientHeight` 都是 761。1180×760 下正文高约 626px，compact 实测 626/626。这两个数值依赖字体与系统，生产实现要在真实字体栈下重新量；允许留 4–8px 余量，超出时先压缩双圆环或行距，不靠隐藏指标换高度。

## 中栏会话概要板

概要板在会话标题之下、轮次列表之上，现有 `sessionBoard()` 已经输出这个位置。它只读当前会话的聚合读数，不发起新读取，也不改变中栏的轮次列表。固定为左右两半：

- 左半是性能读数，三行：
  1. 提示 token、输出 token、费用、缓存命中率。
  2. 首 token、平均耗时、速度 tok/s。
  3. 主链笔数、旁路笔数、峰值占比、重试笔数、模型数。
- 右半是工具使用，三行：
  1. 工具 chip：名称、次数；有失败时追加红色 `N 失败`；放不下的 chip 归入 `+N`。
  2. 写入：文件名 chip 与写入次数，放不下归入 `+N`。
  3. 读取：文件名 chip 与读取次数，放不下归入 `+N`。

左半直接使用现有 `resourceGroup`、`performanceData`、`structureGroup` 的值，右半使用 `toolsGroup` 与两路 `pathGroup`；本文只固定行序、单行规则与断点，不新增计算公式。

### 单行规则

每一行只占一行，这是硬规则：

- 行容器 `display:flex; flex-wrap:nowrap; white-space:nowrap; overflow:hidden`，文本用 `text-overflow:ellipsis`。
- 文件名与工具名在 chip 内省略；次数、失败数、`+N` 不省略。
- 行高不随内容增长，约 17–19px；每行 `scrollWidth` 与 `clientWidth` 相等，不用 `overflow-x:hidden` 掩盖溢出。
- 空间不足时减少展示的 chip 数并入 `+N`，不换行、不横向滚动。

### 断点与层级

- 中栏容器宽度 ≥561px：左右两栏，比例约 1.1fr / 0.9fr，中间 1px `--line` 分隔；左右各 3 行，用 subgrid 让行底对齐。
- <561px：单列 6 行，左半在上、右半在下，分隔线取消。
- 卡片表面、圆角与 1px 边界沿用方向 A 的卡片规则。不用顶部 2px 强调边、单侧光带或渐隐遮罩示意进行中；进行中由刷新时间与在途标记承担，历史请求不带装饰性边与状态标签。这条对全站容器生效，已写入 [UIUX-DESIGN.md](../../../UIUX-DESIGN.md) 通用原则。
- 指标名称用 UI 字体与 `--muted`，数值用等宽与 `tabular-nums`；工具 chip 用 `--inset` 底，失败计数用 `--bad`。

### 数据边界

- 缓存命中率沿用 `contextStatsHtml` 的口径，只统计提示与缓存两个读数都在的请求，分母写进 `title`；平均耗时是已加载窗口的请求平均，不是单笔。
- 工具名、次数、失败状态与写入/读取路径来自会话内工具调用；同一路径多次出现合并计数，归类不了的不写。
- 缺失的指标整行省略或写 `—`，不写 0；没有工具调用时不画右半的空 chip。
- 样张的 128.4k、97 tok/s、64% 与文件计数都是合成值。

### 指标详情

详情面板回答的是「这趟会话的记录质量如何、有没有异常要追」，不是把会话汇总里的字段全列一遍。展开后默认只给图形与三张重点卡，全部明细收进第二级折叠。

**开关位置。** 控件在卡片底部中下方，是一条跨整卡的分隔栏按钮，带可见文字「展开会话指标 / 收起会话指标」、chevron、hover 底色与 focus-visible 描边。不放右上角：22px 的透明角标不易发现，还会逼右半第一行 chip 留 `padding-right` 给它让位，等于控件跟内容抢空间。按钮留在底部，展开时详情出现在按钮上方，收起时按钮位置不变。

**两条堆叠条。** 宽度按占比分段，颜色只表达判定状态，不引入新色板。分母都是 `coverage.calls_total`，条头给出总数：

| 条 | 分段 | 字段 |
| --- | --- | --- |
| 失败位判定 | 失败（`--bad`）、已判定成功（`--accent`）、未判定（`--line-strong`） | `Σ tools[].errors`、`calls_error_known − Σ tools[].errors`、`calls_total − calls_error_known` |
| 参数事实覆盖 | 已提取（`--accent`）、缺口（`--line-strong`） | `calls_fact_known`、`calls_total − calls_fact_known` |

灰段是缺失，不是失败；不画「本地估计」这类正常态说明。段为 0 时整段不画，图例只列非零段。条用 `role="img"` 加 `aria-label`，文字等价物由图例与总数承担。

**三张重点卡。** 各带语义图标、大读数与一行短注（口径进 `title`）。异常态才染 `--bad`，正常态只有图标与数字，不加装饰边。不放「结果可判定」百分比：第一条堆叠条已经把 `calls_error_known / calls_total` 画完，再做一张卡只是把同一组数换成百分比重复一次。

| 卡 | 值 | 图标 | 短注 / 口径 |
| --- | --- | --- | --- |
| 失败调用 | `Σ tools[].errors` | `failure` | `failures_truncated` 为真时标「仅前 200 条」；失败率口径写进 `title`，分母用 `calls_error_known`，注明「未判定不等于成功」 |
| 出现中断的请求 | `interrupts.requests.length` | `gap` | 同一标记跨请求只计一次；`interrupts.unknown` 放明细，不混入卡片 |
| 工具调用 | `coverage.calls_total` | `role-tool` | 副行给工具种类数与技能种类数 |

**可点定位。** `failures[]` 与 `interrupts.requests` 都带 `req_id`，失败调用卡与中断卡可点，复用现有 `data-summary-req`（`web/app.js` 的请求定位）跳到对应请求，不新增读取。中断已有 `summaryEntries` 的 `{kind:'interrupts'}` 查询与 `data-summary-req` 列表可复用；失败数用 `Σ tools[].errors` 避开 `failures_truncated`，定位只取 `failures[]` 里已有的 `req_id`，不要求服务端加「按失败过滤」的查询。

**全部明细。** 默认是收起的一个胶囊按钮，点开才出现三组指标。这一步是面板的关键：把所有字段一次摆出来，等于把「详细」理解成「更多数字」，反而淹没了重点。图形给结论，明细给查证，两层分工。

- **覆盖**：已配对 / 未配对（`calls_paired`、`calls_total − calls_paired`）、失败位已判定 / 失败位未判定、参数事实已提取 / 缺口。
- **异常**：失败调用、失败率、失败调用定位、出现中断的请求、归属未知请求（`interrupts.unknown`）、派生未追上（`dirty`）、费用字段缺失（`totals.cost_absent`）。0 值整格省略，不写 0，也不写 `—` 占位；`dirty` 只在为真时出现。
- **规模**：请求、子代理请求、子代理 actor（`structure.requests_total`、`subagent_requests`、`subagent_actors`）、工具种类（`tools.length`）、技能种类（`skills.length`）、写入路径 / 写入调用（`paths.written.length` / `Σ paths.written[].count`）、读取路径 / 读取调用（同 `paths.read`）。种类数与调用次数分开写：`paths.*.length` 是路径去重后的条数，chip 上的次数是同一路径的调用数，写「写入文件 16」会把两个量纲混成一个。

全部字段来自首屏 `SessionSummary`（`src/queries/session-summary.ts`），**零新增读取、零字段改动**。不复述提示/输出/费用/缓存、首字/平均/速度、主链/旁路/峰值/重试/模型——这些已在概要板三行或右栏用量卡里。

**交互与降级。**

- 两级开关都带 `aria-expanded`、`aria-controls`；Esc 先收明细、再收整块面板。点击卡片外收起整块面板，点击详情内部不收（避免选词时被关掉）；切会话把两级状态都复位为收起。
- 展开有 120ms 的淡入位移，减少动效下不播；两级展开都不触发任何读取。
- 右栏 <560px 时两条堆叠条改单列、三卡仍排三列、明细三组改单列；三档字号下都不折行、不横向滚动。
- 缺字段的指标整格省略；`session_usage` 只在单一 agent 时可读，混多 agent 为 null 时不在卡片里放数值，避免与逐笔 `totals` 相加（`session-summary.ts` 的类型注释已写明两者口径不同）。

## 本次回复折叠

### 摘要

摘要只放两项：`本次回复` 加 `finish: <finish>`，以及块数 `<N> 块`。完整性异常时按现有优先级显示完整性短语，不用 finish 覆盖异常。没有可读回复时显示现有的读取入口或失败原因。

### 展开内容

展开后只有内容块索引，没有元数据行、键值表与下一请求边界：

1. 每个块一行：图标、类型、两行预览；左边线按类型着色，thinking 用 assistant 色，text 用分隔线色，tool_use 用 tool 色。
   - thinking 图标用 `brain`，tool_use 图标用 `role-tool`（扳手），text 用无图标或 `read`。
   - tool_use 行带 `查看工具` 链接，点击切到工具页签并选中该调用；沿用现有选择动作，不新开路由。
   - 预览只用于索引，完整内容在正文页签。
2. 不显示每块 token，也不再加 `内容块 N · 输出 tok` 这类小标题：块数已在摘要行，输出 token 在中栏概要板与用量卡，重复一遍只是占高度。
3. 底部入口 `在正文查看完整回复`，切到正文页签并定位回复首块。折叠内不重复渲染完整回复正文。

### 数据边界

- `ReplyView` 提供 `finish`、`model`、`blocks`、`text`、`thinking`。`blocks` 的 `kind`、`text`、`callId` 可直接用。
- 输出 token、耗时、首 token、首个文本都已经在中栏概要板与用量卡出现，本次回复折叠不再重复；`timingReadingsOf` 的读数由那两处承担。
- 每个块没有协议级的 token 数。样张的 2,840、1,876、96 是合成值，生产不显示每块 token，也不按文本长度分摊。
- 响应 ID 与 HTTP 状态不在读取契约里；样张的 `msg_01H7…` 与 `200 OK` 是示意，不画。
- 空回复、不可读、被回收、读取失效都沿用现有状态与重试入口。

## 请求结构折叠

### 摘要

摘要为消息总数，增量已知且大于 0 时加 `新增 M`。总数未读时写 `消息总数未读取`，不写 0。

### 展开内容

请求结构就是 LLM 请求的原始消息序列，按序号 `#0…N` 一条一行。不压成角色汇总表，也不另开新消息区块：

1. 消息列表是主体，沿用 `renderMessages` 与 `.msg-list`：每行序号、角色徽标、单行预览。工具结果预览以 `Tool result ·` 前缀和等宽字体区分；developer 等注入角色照常显示，不合并进 system。
2. 新增消息只在 `delta` 已知且大于 0 时加 accent 左边线；摘要行的 `新增 M` 是唯一的增量入口。不重复列出同一条消息，不在列表外再画一份新消息。
3. 选中行沿用现有 `aria-current` 淡色底；点击仍联动右侧选择与正文定位，不新开路由。
4. 已读窗口小于总数时，头部写 `已读 X / 共 N`，并保留现有 `加载更早` 与失败重试；序号空洞保留现有 gap 行。
5. 列表下方不再补对比行与缓存断点行：新增数已在摘要行、新增消息已在列表内带 accent 左边线，两行只是把同一件事说第二遍；`删除 D · 保留 K` 与 `cache_control` 位置都不在读取契约里，写出来只能靠推算。前驱不可比时也不补说明，列表本身不标记新增即已表达。

### 数据边界

- 消息来自 `entries`、`structure.ords`、`structure.back/next/total`；增量来自 `deltaOrdinals(detail)`。`prev_relation` 与 `prev_req_id` 只用于判断链是否可信，不画成对比行。
- 逐消息 token 没有稳定字段。不显示 token 列，不用请求总量倒推，也不按文本长度分摊。样张的 11 条消息与 2 条新增是合成值，`#8` 缓存断点没有对应字段。
- 请求结构的 token 合计与用量卡里的 prompt token 不是同一层口径。没有逐消息 token 时，不把两者相加，也不互相校验。

## 工具清单与技能清单

工具与技能从现有能力折叠拆成两个折叠，数据仍来自 `renderCapabilities` 消费的 `CapabilityView`：

- 工具清单摘要显示工具数；展开后是名称 chip 与现有状态说明。工具 schema、调用详情与 `工具` 页签保持独立，折叠里不做第二份浏览器。
- 技能清单摘要显示技能数；展开后是技能名 chip。没有技能页签，这里是技能清单的唯一入口。
- 能力缺失、未识别、部分可读等状态沿用现有文案与颜色；正常态不加说明标签。

## 用量与上下文卡

### 头部

`ctx-gauge` 图标、`用量与上下文`、折叠箭头。默认展开；点击可整体收起，收起后四格指标也不显示。卡片没有副标题，没有重复的说明句。

### 四格指标

沿用 `contextStatsHtml` 的口径，不重算：

| 指标 | 主值 | 副行 | 缺值 |
| --- | --- | --- | --- |
| 已用上下文 | prompt tokens | 总窗口与已用比例；窗口未知时写窗口未知 | 写 `—` 与缺什么 |
| 固定开销 | 固定类别 token 合计 | 占已用比例 | 写 `—`，不写 0 |
| 提示词缓存 | 命中率 | 缓存读数未上报时写原因 | 写 `—` |

### 双圆环

两张圆环都按**选中的轮次**读数，但两侧的事实粒度不同，必须分别写清，不能都标「会话」：

- **Token 圆环是轮次末笔请求的上下文构成**。取该轮最后一次请求：输入侧按 `prompt.parts` 分类，输出侧按该笔回复分类，中心是两者之和。不跨请求相加——每笔请求都重发完整上下文，相加会把同一段系统提示重复计入几十次。标题右侧是该笔的缓存命中。
- **耗时圆环是整个轮次的活跃时长**。轮次跨多笔请求，模型生成时间在每笔的 `ms` 里，工具执行时间在相邻两笔之间（`exec_ms` 是结果请求开始时刻减调用请求结束时刻，落在调用请求的 `ms` 之外）。所以只有按轮次求和才能把两类时间放进同一个环：`Σ ms + Σ exec_ms`。
- 两侧口径不同不是缺陷：一个回答「此刻上下文里是什么」，一个回答「这一轮的时间花在哪」。两个标题各自写清口径，读者不会误当成同一个数。
- 会话级读数已经有自己的家：中栏概要板第一行是会话合计，会话头合计行是同口径另一处。两张圆环不再造第三个会话总数。
- 样张里的 133.2k 与 12m29s 都是合成值。轮次的请求集合可以由 `listTurns` 的 `start_req`/`reply_req` 与 `turnRequestIds` 的同一条区间规则取到，不需要新表。

四格下方并排两张等宽卡，位于矩阵树状图之上：

1. **Token 统计**：数据库图标、标题、右侧缓存命中；圆环中心是该轮末笔请求的输入加输出 token。图例分两段：输入侧按 `prompt.parts` 的正值 `kind` 逐类列出，次序固定为 `系统提示`、`工具定义`、`记忆`、`文件引用`、`工具结果`、`对话内容`、`技能`、`Harness`，未知 `kind` 原样缀后；输出侧固定两类 `模型思考`、`模型回复`。输出侧没有分类字段时只画输入侧，中心写输入 token 并在 `title` 说明输出未分类，不把输入量冒充总量。
2. **耗时统计**：时钟图标、标题、右侧输出速度；圆环中心是该轮活跃时长，图例只列有字段的阶段，每行名称、时长与次数或内容块数，占比只在 `title`。底部是 6px 时间轴，按同一批阶段分段，刻度由各段时长累加得出。
3. 两张卡都用 `--surface` 底、1px `--line` 环、8px 圆角；圆环 70px、环宽 10，段间留 0.8 单位缝隙。圆环本身 `aria-hidden`，文字等价物由中心读数与图例行承担。
4. 480px 右栏下两张卡并排，各约 212px；低于 360px 的右栏宽度改为单列堆叠，不横向滚动。
5. full 面板高约 134px，compact 约 131px；compact 只把圆环缩到 64px、内距减 1–2px，图例与时间轴都保留。

### 图例与跨图联动

- Token 图例每行：色点、类别名、占比、token；按固定类别次序排列（输入侧 8 类在前、输出侧 2 类在后），不按占比重排，这样同一位置在不同请求间指向同一类别。百分比保留一位小数，合计 100%。
- 耗时图例每行：色点、类别名、时长 · 次数或块数；占比放 `title`，因为 212px 宽的图例放不下四列而不截断。
- 图例行是可点按钮。点一行后，两张圆环、时间轴与矩阵树状图同时只点亮对应分类，其余压到 28% 透明度；再点同一行取消。`aria-pressed` 承载状态。
- 联动只在有真实对应的类别间成立。按现有字段只有一对：Token 侧的 `工具结果` ↔ 耗时侧的 `工具执行`——工具执行时间花在产出这些结果上，两者指同一批调用。其余类别点选后只点亮自己，并在 `title` 写明另一张图没有对应阶段。
- 服务端补上输出侧分类后，`模型思考` 与 `模型回复` 两对才成立（token 侧的输出类别 ↔ 耗时侧的对应阶段）；在那之前不预埋映射，也不拿 `对话内容` 顶替 `模型回复`。
- 颜色用一条 `--cat-1` 到 `--cat-8` 的蓝到灰单色阶，由深到浅表示占比高低。三幅图共用同一条色阶与同一分类次序，模块内不再引入第二套色相；这是 Pis 指定的克制配色要求，方向 A 的蓝色预算不变。

### 矩阵树状图

保留原有的矩阵树状图，位置在双圆环之下、构成明细之上：

- 数据与布局沿用 `context-map.js` 的叶子与切分算法，交互式 treemap 不整块 `aria-hidden`。
- 瓦片按分类取 `--cat-*` 的淡染底与同色描边，面积表示 token 占比。高度固定 112px，compact 92px；按真实像素切分再折回百分比，避免窄栏把瓦片拉成扁条。
- 瓦片只有放得下名字（≥18px 高、≥30px 宽）才显示文件名，放得下读数（≥32px 高、≥50px 宽）才显示 token 与占比；其余只留色块，信息在 `title` 与构成明细里。
- 树状图只铺输入侧叶子，瓦片颜色只取输入侧类别；输出侧两类没有叶子，不画瓦片，避免与 Token 圆环的段数对不上。
- 树状图下方的旧图标图例与分类参数行删除：双圆环的图例已经承担同样的分类、数值与占比，重复一份只是占高度。构成明细保留。

### 构成明细

- 默认收起为一行 `构成明细 · 全部 N 项`，展开后按 token 降序列出全部叶子；名称过长省略，块内不换行。
- 列表复用现有 `contextRowsHtml` 的完整列表与点击行为，与树状图、Token 圆环的输入侧来自同一份 leaves，不发起第二次读取。
- 输出侧两类（模型思考、模型回复）只在圆环里出现，没有叶子可展开，不进树状图也不进构成明细：它们是同一段流式产出的时间与 token 汇总，没有文件或条目身份。
- 标签只在已有分类语义时出现，例如 skills、project、user、tool、result；没有来源就留空，不造标签。

### 脚注与用量明细

- 卡片底部一行显示输入、输出、费用；compact 隐藏这一行，因为会话提示卡已经给过同样的数。
- 现有 `用量明细` 折叠保留，缓存读/写、reasoning、effort 等字段不能丢。输入、输出、费用只在脚注出现一次，`用量明细` 里不重复；其余字段留在明细里。
- 缺失值写 `—` 或省略，不估算费用，不用默认价目表。
- 现有 `分类是估计分配` 这类正常态说明收进 `title` 或只在估算/缺失时显示一行弱化脚注。正常态不再固定多一段解释。

样张的 128.4k、66.4k、48%、2.8s、51 项、$0.284、双圆环的 133.2k 与 12m29s 都是合成值，不能作为生产默认值。

### 规则

- 新增字段先走 `src/read-contract.ts` 与现有读取路径，按 [读取功能接入规则](../../../../docs/read-feature-rules.md) 定用途、owner 与预算。页面不直接 `fetch`，不在展开折叠时临时发请求。
- 所有正文、路径、模型名、ID 与标签一律转义；不插原始 HTML。
- 正文、账号、令牌、用户配置不进 fixture、日志、页面样张或提交。样张只含合成数据。
- 缺失就写缺失。不把缺失画成 0，不用旧结果冒充当前结果，不按长度分摊 token，不猜缓存断点、响应状态或下一步请求。
- 耗时圆环的每一段必须来自实际计时字段；不按请求数、工具次数或段数平均，也不用总时长倒推分段。
- 请求结构、回复块、上下文构成是三层不同口径。没有逐消息或逐块 token 时，不做跨层相加，不互相校验。

### 服务端配合

这版界面有几处不是纯前端重排，服务端必须一起改；不先落这些，前端只能画合成值。每一项都按 [读取功能接入规则](../../../../docs/read-feature-rules.md) 的五步交付，不新增直接 `fetch` 与临时路由。

| 界面需要 | 现状 | 服务端要做什么 |
| --- | --- | --- |
| Token 圆环的输入侧 8 类 | `prompt.parts` 的 `kind` 是 `system`、`tools`、`memory`、`files`、`results`、`chat`、`skills`、`harness`（`web/parts.js` 的 `PARTS`），只来自 magpie 的 `prompt.parts`；OTLP 与会话适配器都不产出 | 前端把现有 8 个 `kind` 直接当圆环类别，**不新增后端分类**，也不改名。缺 `prompt.parts` 的请求不画输入侧圆环，写现有「没有路由侧的 prompt 分析」 |
| Token 圆环的输出侧两类 | `out_tok` 只有一个总数，回复块的 token 数不在协议里（`ReplyView.blocks` 没有 token 字段） | 要画 `模型思考` / `模型回复` 两段，得在读取契约里加输出侧分类：优先用上游已给的 `reasoning` token（`request.reasoning`，仅部分来源有），剩下的归 `模型回复`。**只有 `reasoning` 读数存在时两段才都成立**；读数缺失就整块不画输出侧，不按正文长度分摊 |
| Token 圆环中心 | `prompt.tokens` 是单笔提示总量，`out_tok` 是单笔输出总量 | 中心写 `prompt.tokens + out_tok`，两者都在才算；缺一个就写现有的那个并在 `title` 说明另一个未上报。这是单笔口径，不是会话 |
| 耗时圆环的四段 | 每笔请求有 `ms`、`ttft_ms`、`first_text_ms`、`reasoning_span_ms`（推理段，需 `firstReasoning` 守卫）；工具配对给 `exec_ms`，它落在调用请求的 `ms` **之外** | 轮次内求和：`模型等待` = `Σ ttft_ms`，`模型思考` = `Σ reasoning_span_ms`（缺一笔就不计入，并在 `title` 写有读数的笔数），`工具执行` = `Σ exec_ms`，`模型回复` = `Σ (ms − ttft_ms − reasoning_span_ms)`，`其他开销` = 轮次活跃时长减去以上四段，为负时不画。四段都以有读数的请求为分母，不用平均补缺 |
| 耗时圆环的 `工具参数` 与样张的 6 段 | 工具参数由模型在生成中输出，与思考、正文共享同一段流式时间，协议里没有逐块时间戳；样张把它单列是合成值 | 不画这一段。要画得在派生阶段给每个内容块落到达时刻，属于新事实，另写 note；在那之前把工具参数时间留在 `模型回复` 段里，不拆假段 |
| 轮次活跃时长的边界 | `listTurns` 给 `start_req` 与 `reply_req`；`turnRequestIds` 已用「首笔开始时刻到末笔开始时刻」圈出同轮请求 | 直接复用同一条区间规则取轮内请求，`Σ ms + Σ exec_ms`。轮内最后结果请求之后的收尾时间不计入，`title` 说明边界 |
| 缓存命中率进圆环标题 | `cacheHitOf` 只看单笔 `cache_read ÷ (in_tok + cache_read)` | 直接复用；会话级命中已有 `summary.totals.cache_hit`。两处口径不同，界面要标出是单笔还是会话 |
| 输出速度进圆环标题 | `timingReadingsOf` 的 `out_tok ÷ (ms − ttft)` | 直接复用。会话级速度在 `timingSummary` 里已有，按同一公式聚合，不新写公式 |
| 中栏概要板的工具失败数 | `summary.tools[].errors` 已有，`error_known` 单独可读 | 直接复用，不新增字段；未判定的调用数用 `count − error_known` 在展示层算 |
| 中栏概要板的写入/读取路径 | `summary.paths.written` 与 `.read` 已有，按 `arg_path` 分组 | 直接复用。`arg_path` 只覆盖 Edit/Write/Read 与 OMP 同族，其他工具的文件参数不补 |
| 指标详情的两条堆叠条 | `coverage.calls_total`、`calls_error_known`、`calls_fact_known` 与 `Σ tools[].errors` 已有 | 直接复用；失败位三态里「已判定成功」＝`calls_error_known − Σ errors`，灰段＝`calls_total − calls_error_known`；段为 0 不画 |
| 指标详情的三张卡 | `Σ tools[].errors`、`interrupts.requests`、`coverage.calls_total`、`failures[]` 已有 | 直接复用，不新增字段；失败数用 `Σ tools[].errors` 避开 `failures_truncated`，定位取 `failures[]` 的 `req_id` 复用 `data-summary-req`，不要求服务端加「按失败过滤」查询 |
| 指标详情的全部明细 | `SessionSummary` 的 `structure`、`coverage`、`tools`、`skills`、`interrupts`、`paths`、`dirty`、`totals` 已覆盖全部指标 | 直接复用，不新增字段；`dirty` 只在为真时出现，0 值整格省略 |
| 待办卡的来源行 | `TodoSnapshot` 只有 `seq` 与 `items`，没有来源请求 | 不显示来源行；要显示得在 `TodoSnapshot` 加 `source_req`，由 Parser 在折叠时记下更新来自哪一笔请求 |
| 待办卡的状态图标 | `TodoItem.status` 保留各家原词（`pending`、`in_progress`、`completed`、`done`、`cancelled`…） | 展示层做一份 `done` / `doing` / 其余 的归类表，不要求服务端归一；归类表在 `web/todo-tab.js` 与测试里各一处，不散落 |
| 回复折叠的块数 | `ReplyView.blocks` 已是数组 | 直接复用 |
| 请求结构的新增边 | `deltaOrdinals(detail)` 已有，且只在 `current` / `prefix` 时可信 | 直接复用；不要为了让更多行有新增标记去放宽 `chain_state` 门控 |
| 设置页的桌面项 | `src/settings.ts` 已有 schema 与权威写入 | 只接入口，不扩 schema；窗口尺寸与位置按用户设置 note 不进设置 |

新增读取操作的判据只有一条：**现有事实回答不了界面问题**。上表里可以直接复用的项目占多数；真正需要服务端新写的是输出侧 token 分类、会话级计时聚合，以及两个阶段时长的派生列。这三项各自单独提 note、单独验收，不塞进这版界面重构一起交付。

前端在服务端就绪前必须能降级：缺输出侧分类就只画提示侧的正值类别（`系统提示`、`工具定义`、`记忆`、`文件引用`、`工具结果`、`对话内容`、`技能`、`Harness`，按 `prompt.parts` 实际有的 `kind` 取），省略 `模型思考` 与 `模型回复` 两段；缺阶段时长就把耗时圆环画成 `模型等待` / `工具执行` / `其他开销` 三段。降级不是留白，是不画没有字段的段。

## Alternatives considered

**Electron。** 生态成熟，前端调试路径熟悉，但多一层 Chromium 与 Node，内存和体积都更大，还要处理主进程与渲染进程的权限边界。Tauri 2 用系统 WebView，壳更薄，符合本机单用户工具的体积预期。代价是 WKWebView 的兼容性与 Rust 构建链要单独验证。Pis 已选定 Tauri 2，这里只记录代价。

**两种宿主都套固定窗口。** 样张早期版本把桌面窗口、舞台底色与圆角投影当成默认形态，浏览器打开时也留一圈灰边。否决：固定尺寸与窗口边框只属于 Tauri 外壳，浏览器路径铺满视口；`?host=desktop` 是唯一分岔，不换成第二套页面骨架。

**让 Tauri 自带服务进程。** 外壳启动时顺手拉起采集器，看起来更自足。否决：采集器已由 launchd `KeepAlive` 托管，再起一个会双写、双扫、抢同一个 SQLite 库；同时会把进程管理权限带进页面外壳。外壳做纯客户端，服务仍归 launchd。

**保留 640px 右栏。** 1440×900 下 640px 右栏会把中栏压到 544px。480px 让中栏回到 704px，右栏用两列与紧凑字号承载同样信息。用户仍可拖到 640。

**把完整回复正文留在本次回复折叠。** 现有实现就是这样，展开后信息量大，但右栏会变成第二份正文，并与正文页签重复。改为摘要加正文入口，完整内容只在一处。代价是看长回复要多一次点击。

**把请求结构压成角色汇总。** 角色表加消息条看起来更短，但请求结构就是 LLM 请求的原始消息序列：每条消息的序号、角色和预览都要能定位，工具结果与 developer 注入也在序列里。汇总会抹掉顺序与逐条预览，消息定位、空洞标记、读取更早与配对详情也无处附着。否决：保留有序列表，汇总信息只出现在摘要行的总数与新增数。

**图例与构成明细始终全量展开。** 首屏会回到满高，且多数时候只看前几项。改为构成明细默认收起、一次点击看全量；双圆环图例本身全量可见。代价是多一次展开。

**本次回复保留响应元数据、键值表与下一请求边界。** 这三块在原稿里占掉折叠内一半高度，而它们的内容在别处已经有了：finish 在摘要行，输出 token、耗时、首 token 与首个文本在中栏概要板与用量卡，块数在摘要行。响应 ID 与 HTTP 状态根本不在读取契约里，下一请求 ID 也没有可推的字段。留着只会让每个读回复的人先扫一遍重复数字。否决：折叠内只留内容块索引与正文入口。

**请求结构列表下方保留对比行与缓存断点行。** 新增数在摘要行，新增消息在列表内已有 accent 左边线，再写一遍是同一件事的第三次表述；`删除 D · 保留 K` 与 `cache_control` 的落点都不在读取契约里，写出来只能靠推算。否决：列表下方不补任何行，前驱不可比时也不加说明。

**保留 treemap 并叠加双圆环。** 两套构成图会重复信息，也会吃掉首屏高度；但树状图承担文件级的空间分布，圆环承担类别级的比例，两者回答的问题不同。保留两者，删掉树状图下方重复的图标图例与参数行，并让图例选中同时联动三幅图。代价是首屏多约 120px。

**把耗时统计放到中栏概要板。** 中栏已有会话性能三行，圆环能承载展开细节；但 Pis 指定嵌入右栏用量模块，且中栏每行单行的规则会与圆环高度冲突。按右栏实现，中栏只保留三行读数。

**把会话指标详情做成弹层或独立页签。** 放进弹层会让读者在两处对照，也夺走了「概要板就地展开」的语境。否决：在概要板底部就地展开，点外或 Esc 收起。

**把九格平铺改成更多格。** 首轮按覆盖/异常/规模三组重排后仍有二十多个数字，一眼看去还是一整片指标，没有重点。否决：展开后默认只给两条堆叠条与三张重点卡，全部明细收进二级折叠，图形给结论、明细给查证。

**保留「结果可判定」百分比卡。** 它取 `calls_error_known ÷ calls_total`，与第一条堆叠条是同一组数换成百分比，只是重复一遍。否决：删掉该卡，覆盖度由堆叠条承载。

**把展开开关留在右上角。** 22px 透明角标不易发现，还逼右半第一行 chip 留 `padding-right` 让位。否决：移到卡片底部中下方，做成带文字的整条分隔栏按钮。

**保留进行中请求的橙色顶边。** 顶边 2px 强调色在圆角卡片上像一条括号，Pis 明确不要这种渐隐边式装饰；进行中状态已有刷新时间与在途标记。否决：卡片四周统一 1px 细线，状态不靠边缘光带表达，规则写入 [UIUX-DESIGN.md](../../../UIUX-DESIGN.md)。

**把双圆环拆成两张独立卡。** 会多出一层卡片边界与间距，首屏高度不够；并排嵌套在用量卡内更紧凑，收起用量卡时两张圆环一起收起。

**马上迁到 IconPark。** 样张的图标风格更接近 IconPark，但生产刚完成 Lucide 迁移，几何、线宽、许可与测试都要重做。继续 Lucide，按语义补图标；IconPark 只做视觉参考。

**把逐块与逐消息 token 画出来。** 样张有这些数，协议与现有读数没有稳定字段。否决按文本长度分摊，也否决用请求总量倒推。没有字段就不画；如果确实需要，另开读取契约扩展，单独验收。

**在设置层里加窗口恢复。** 用户设置 note 已明确窗口恢复状态不进设置。本文不在外壳里偷偷加一套窗口状态存储；窗口每次以默认尺寸打开，用户自己拉伸。

## Acceptance criteria

### 外壳

- 1440×900 默认打开，最小 1180×760，可四边拉伸；macOS 原生交通灯可用，顶栏空白区可拖动。这组尺寸只在 `?host=desktop` 生效。浏览器直接打开时页面铺满视口：三栏边界贴齐窗口边缘，`#app` 的 `clientWidth` 等于视口宽度，没有舞台底色、四周留白、圆角、投影与页面级 `max-width`；缩放浏览器窗口时三栏跟随视口变化，44px 顶栏不变。
- 窗口加载 loopback 服务，`?host=desktop` 生效；服务未启动时显示失败页与重试，不出现第二个采集器进程。
- 页面拿不到 fs/shell/IPC；Tauri capability 只含窗口所需的最小项。
- 浏览器直接打开 `http://127.0.0.1:8320` 时仍是现有页面，44px 顶栏，行为不变；两种宿主共用同一份三栏网格与读取路径。

### 中栏

- 1440×900 下概要板左右两栏各 3 行，左右行底对齐；每行高不超过一行文字，行内 `scrollWidth` 与 `clientWidth` 相等，不出现第二行与横向滚动。
- 1180×760 下概要板单列 6 行，仍每行一行；文件名 chip 用省略号截断，`+N` 保留。
- 左列读数沿用现有会话聚合，缺失时不显示 0；右列失败计数只在非零时出现；卡片四周统一 1px 边界，进行中不加顶部强调边或渐隐遮罩。
- 展开开关在卡片底部中下方，是跨整卡的分隔栏按钮，带可见文字、hover 与 focus-visible；点开后两条堆叠条与三张重点卡出现，全部明细默认收起，`aria-expanded` 与 `aria-controls` 同步。
- 两条堆叠条的分段合计都等于 `coverage.calls_total`，段为 0 时不画；失败位三态与参数事实两态的颜色只表达判定状态，灰段是缺失不是失败。
- 三张卡是失败调用、出现中断的请求、工具调用，不出现「结果可判定」百分比；异常态才染状态色；失败卡与中断卡可点并复用 `data-summary-req` 定位，不新增读取。
- 点击卡片外或按 Esc 分级收起（先明细、再整块），点击详情内部不收，切会话两级状态都复位；两级展开都不触发读取。
- 全部明细里 0 值整格省略，种类数与调用次数分开写；三档字号与 1180 单列下不折行、不横向滚动，缺字段整格省略。

### 右栏

- 1440×900、480px 右栏，正常选择且无证据折叠时，默认读数页无纵向滚动；`scrollHeight` 与 `clientHeight` 差值不超过 8px。
- 1180×760 进入 compact，默认读数页仍无纵向滚动；四格、双圆环图例、矩阵树状图与构成明细入口都在。
- 右栏 280px 时无横向滚动；页签进入图标模式，`title` 与 `aria-label` 完整；280px 允许纵向滚动。
- 四折叠默认收起，摘要行显示 finish、消息数、新增数、工具数、技能数；展开后细节可读，状态按请求持久化。
- 本次回复显示内容块索引与正文入口；工具链接切到工具页签并选中调用；折叠内不重复完整正文，也不再重复输出 token、耗时、首 token、首个文本与响应 ID。
- 请求结构显示有序消息列表：序号、角色徽标、单行预览、新增蓝色左边、选中淡色底与空洞；不出现角色汇总表、独立新消息区块，也不在列表下方补对比行与缓存断点行。
- 用量卡四格口径与 `contextStatsHtml` 一致；Token 圆环的段数与图例一一对应、合计 100%，段数等于正值输入 `kind` 数加输出侧段数（有 `reasoning` 读数时 2 段、否则 0 段），没有输出侧分类时不多画段；耗时圆环只画有字段的段（模型等待、模型思考、工具执行、其他开销），缺字段的段整段不出现而不是画成 0；时间轴刻度由各段时长累加得出；480px 两卡并排与 280px 单列都无横向滚动；矩阵树状图保留 51 个叶子、瓦片按像素切分不拉成扁条；点图例后两张圆环、时间轴与树状图同步点亮与压暗，再点取消，无对应阶段的行只点亮自己；构成明细展开可读全部叶子；脚注只在 full 出现，`用量明细` 字段不丢。
- 服务端未提供输出侧分类与会话级计时时，界面按降级形态工作：Token 侧只出现有 `kind` 的提示侧类别、耗时侧 3 段，不显示空段、不写 `—` 占位段、不在前端按长度分摊。降级形态与完整形态都要有测试覆盖。
- 待办页签计数等于未完成项数；待办卡进度与状态正确；没有来源字段时不拼来源行。
- 正常态没有多余说明文字与状态标签；异常标签只在异常时出现。

### 视觉与图标

- 方向 A 令牌不新增第二套色板；页签选中是中性文字加 accent 下划线。
- 新增字号全部乘 `--fs-scale`；三档字号下无横向滚动，垂直方向允许滚动。

- 刷新在加载时旋转 480ms；减少动效下不旋转；折叠箭头与页签下划线同样降级。

### 可访问性与 i18n

- 页签 `role=tab`、`aria-selected`、`aria-controls` 与方向键切换可用；折叠用原生 details，键盘可开合。
- 请求结构的每行是 `<button>`，可访问名由序号、角色与预览拼成，新增状态也读进名字里；不用视觉色块代替语义。
- 双圆环 `aria-hidden`，文字等价物由中心读数与图例行承担；图例行本身是可点按钮，带 `aria-pressed`，键盘可聚焦与切换；矩阵树状图外层 `role="img"` 带 `aria-label`，单块靠 `title` 补名称与占比。
- 中英字典键齐全，无缺失；新增文案不进 HTML 内联中文。
- 焦点环可见；颜色不是唯一状态信号。

### 测试与安全

- `bun run typecheck` 通过；`tests/web.test.ts`、`tests/body-view.test.ts`、`tests/todo-tab.test.ts`、`tests/i18n-coverage.test.ts`、`tests/http.test.ts`、`tests/read-boundaries.test.ts` 通过；`bun run verify:notes` 通过。
- 新 web 模块已登记 `STATIC_FILES`；页面不新增直接 `fetch`，不新增 HTTP 路由。
- 测试只用合成数据；真实正文、账号、令牌与用户配置不进 fixture、日志或提交。
- 真实流量只读验收单独记录：抽取若干请求，比对 finish、输出 token、耗时、构成与待办；不写库。

## Risks

- **高度卡得太紧。** 样张 761/761 是在特定字体和截图上量出来的。生产系统字体、`--fs-scale`、英文文案都会改变高度。允许 4–8px 余量，超出时先压双圆环高度与行距；仍然超出就让右栏滚动，不隐藏指标。
- **分类色阶仍可能显得花。** 8 个类别共用一条 `--cat-1` 到 `--cat-8` 的蓝到灰单色阶，不再用彩虹色；浅色端与灰端的区分度靠明度差。低对比显示器上相邻两档可能难辨，此时靠图例顺序、数值与 `title` 兜底，不回到多色方案。
- **耗时统计没有完整数据。** 模型等待可用 TTFT，工具执行可由配对时间推，思考、工具参数与回复阶段现有读数没有稳定字段。没有字段就不画估算段；先用 `其他开销` 兜底，或整块不画。样张的 12m29s 与 6 类占比都是合成值。
- **概要板单行规则被字体撑破。** 中文字体、`--fs-scale` 与长文件名都会改变 chip 宽度；规则是每行 `nowrap` 加省略，不靠换行或横向滚动。验收覆盖三档字号与英文长文件名；如果 chip 截到不可辨认，先减少展示 chip 数并入 `+N`，不放开换行。
- **请求结构又被做成聚合摘要。** 样张早期版本曾用消息条与角色表替代有序列表，看起来像结构，实际丢掉了消息序号、顺序与逐条预览。实现时若再出现 `更短的汇总`，以有序列表一节为准。
- **WKWebView 差异。** `color-mix`、容器查询、`backdrop-filter` 与滚动行为在 macOS WebView 上可能与 Chrome 不同。P0/P1 就要在真实窗口里验证；必要时降级为预设半透明色与固定宽度，不引入 Chromium-only 写法。
- **默认折叠改变阅读习惯。** 本次回复从默认展开改为默认收起，用户要多点一次。摘要行保留 finish，且按请求持久化开合状态；如果真实使用中打开率很高，再评估是否把本次回复恢复为默认展开并收起用量卡。
- **样张数字被误抄。** 样张含 51 项、11 条消息、11,784 token 等合成值。实现与测试都不得把它们当默认值或 fixture。逐块与逐消息 token、缓存断点位置、响应 ID 现有读数都没有稳定字段，不能按长度分摊，也不能画。
- **右栏信息仍然多。** 四折叠加用量卡在 1180×760 下靠 compact 才放得下；字号放大或英文长文案可能破坏无滚动目标。验收覆盖三档字号与中英，不通过就允许滚动，不缩到不可读。
- **桌面外壳的权限边界。** 页面加载自 loopback，仍不应拿到 Tauri IPC。若后续为了窗口控制或文件导出开放命令，必须单独写威胁模型、最小 capability 与测试，不能顺手打开 `fs` 或 `shell`。
- **服务不可用时的体验。** 外壳不自动拉起采集器，服务未启动时只能看失败页。这符合生命周期边界，但用户可能期待双击即用。是否让外壳管理 launchd 是另一个决策，不在本文范围。
- **图标映射的光学差异。** Lucide 与 IconPark 的网格、线宽与圆角不同，样张的图标密度不能一比一复制。按 Lucide 现有 24 网格与 2.25 描边落地，必要时单独调尺寸。
- **构建与分发。** 签名、公证、自动更新、应用图标与首次启动提示都不在本文范围。P0 只要求本机可运行；对外分发另写 note。
- **真实流量与合成验收混淆。** 样张与 fixture 只能证明布局与状态。生产验收要单独用真实只读流量，报告里分开写，不把合成截图说成真实流量结果。
